    What to look at

    • By code. Time out, Interrupted and Crash each word the failed bubble by the RUN_ERROR code, not the server's message.
    • Id too long. Shows the server's own message, which names the field and limit, and an offer (part run-error-offer) to start a new conversation.
    • Refused POST. The run POST is answered with a 400 before streaming: the bubble shows HTTP 400 and its body.

    What to look at

    • Redrawn in place. Release form draws a host renderer's form, then redraws it five seconds later. Type into it meanwhile: the field keeps its value and focus, since the renderer updates the node it is handed.
    • A run from a button. Its Submit starts a run with chat.run, forwarding the name as props with a user turn of its own. Name the release refuse: refused once, its Retry sends the same action and run id. Reload the tab and the form comes back inert, marked from history.

      What to look at

      • A live view. This page imports the third vendored file and calls registerMcpApps(chat, { url: "/mcp-apps/" }). "A view with a server" draws ui://sales/week.html in a sandboxed frame once it scrolls into sight; the view says who initialised it and shows its tool input and result.
      • The bridge. "Refresh" sends tools/call through the route and the result updates; "Ask the agent" sends ui/message, which arrives as your next message. Toggle the theme: the view is told, and recolours from the chat's tokens. The frame takes the view's height.
      • Consent. Neither runs unseen: each tools/call and ui/message raises a confirmation card under the frame, naming the tool and its arguments or showing the message's text. Cancel, and the view's log reads "refused (-32000): Tool call denied" or "Message sending denied"; Confirm, and it runs. "A view that calls on load" calls its tool before anyone clicks: the card is there as the view appears, and the result waits for it. In full screen the card is pinned under the frame. Two clicks of "Refresh" ask one card at a time.
      • Full screen. "Full screen" sends ui/request-display-mode: the view covers the page in the same frame (its log and result stay, so it did not reload), with an "Exit full screen" control. Escape, that control, or "Back inline" returns it to the transcript at the height it had. A stored view stays inline.
      • Without a server. A view whose toolset has no id draws the notice, whatever is registered.
      • Strings. The notice's words come from chat.uiStrings, so a host localised through data-strings keeps them.
